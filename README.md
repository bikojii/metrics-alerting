# Metrics Alerting

Учебный сервис сбора метрик на Go. Агент периодически читает показатели собственного Go-процесса и отправляет их HTTP-серверу. Сервер хранит значения в памяти, предоставляет API для чтения и HTML-страницу со списком метрик.

В текущей версии реализован сбор метрик. Правил алертинга и уведомлений пока нет.

## Возможности

- Сбор 16 показателей `runtime.MemStats`, метрики `RandomValue` и счётчика `PollCount`.
- Два типа метрик: `gauge` заменяет значение, `counter` прибавляет дельту.
- Независимые интервалы сбора и отправки: медленная отправка не останавливает сбор.
- Потокобезопасное хранилище с отдельными пространствами имён для gauge и counter.
- Проверка адреса, интервалов и числовых значений; обработка HTTP-ошибок и таймаутов.
- Завершение по `Ctrl+C` / `SIGTERM`. Сервер ожидает завершения активных запросов до 5 секунд.

## Быстрый запуск

Требуется Go 1.24.2 или новее. База данных и дополнительные сервисы не нужны.

```sh
git clone https://github.com/bikojii/metrics-alerting.git
cd metrics-alerting
go mod download
```

В первом терминале запустите сервер:

```sh
go run ./cmd/server
```

Во втором — агент:

```sh
go run ./cmd/agent
```

Агент собирает первую порцию метрик сразу, затем каждые 2 секунды. Отправка выполняется каждые 10 секунд. После первой отправки откройте [список метрик](http://localhost:8080/) или запросите значение:

```sh
curl http://localhost:8080/value/counter/PollCount
```

В Windows PowerShell можно использовать `curl.exe` вместо `curl`.

## Конфигурация

| Процесс | Флаг | По умолчанию | Назначение |
| --- | --- | --- | --- |
| Сервер | `-a` | `localhost:8080` | Адрес прослушивания `host:port` |
| Агент | `-a` | `http://localhost:8080` | Адрес HTTP(S)-сервера |
| Агент | `-p` | `2` | Интервал сбора в секундах |
| Агент | `-r` | `10` | Интервал отправки в секундах |

```sh
go run ./cmd/server -a localhost:9090
go run ./cmd/agent -a http://localhost:9090 -p 1 -r 5
```

Агент принимает адрес без схемы (`localhost:9090`) и добавляет `http://`. Интервалы должны быть положительными. Адрес должен указывать на корень сервера, без пути, параметров запроса и учётных данных. Переменные окружения и конфигурационные файлы не используются.

## HTTP API

### Обновление

`POST /update/{type}/{name}/{value}`

Тип — `gauge` или `counter`. Значение gauge — конечное число `float64`, counter — целое `int64`. Тело запроса не требуется. Имена следует кодировать как сегмент URL.

```sh
curl -X POST http://localhost:8080/update/gauge/temperature/23.75
curl -X POST http://localhost:8080/update/counter/requests/5
curl -X POST http://localhost:8080/update/counter/requests/2
```

Успешный ответ: `200 OK`, тело `OK`. В примере счётчик `requests` будет равен `7`.

### Чтение

`GET /value/{type}/{name}`

```sh
curl http://localhost:8080/value/gauge/temperature
curl http://localhost:8080/value/counter/requests
```

Ответ: `200 OK`, `text/plain; charset=utf-8`, значение без принудительного округления до трёх знаков.

### Общий список

`GET /` возвращает HTML-страницу. Метрики отсортированы по имени и типу, имена экранированы.

### Ошибки

| Статус | Причина |
| --- | --- |
| `400 Bad Request` | Неизвестный тип или некорректное число, включая `NaN` и бесконечность |
| `404 Not Found` | Метрика не найдена либо путь не соответствует маршруту |
| `405 Method Not Allowed` | Метод не поддерживается маршрутом |

## Метрики агента

| Группа | Метрики |
| --- | --- |
| Память | `Alloc`, `HeapAlloc`, `HeapIdle`, `HeapInuse`, `HeapObjects`, `HeapReleased`, `HeapSys`, `StackInuse`, `StackSys`, `Sys` |
| Аллокации | `Mallocs`, `Frees` |
| Сборщик мусора | `NumGC`, `LastGC`, `PauseTotalNs`, `GCCPUFraction` |
| Дополнительные | `RandomValue`, `PollCount` |

Показатели runtime передаются как gauge, даже если исходное поле накопительное. Единицы соответствуют `runtime.MemStats`: например, `Alloc` — байты, `LastGC` — Unix-время в наносекундах, `PauseTotalNs` — наносекунды. Преобразование больших целых значений в `float64` может снижать точность.

`RandomValue` — случайное значение в диапазоне `[0, 100)`. `PollCount` — число выполненных сборов. Агент отправляет дельту с последней подтверждённой отправки; после успеха вычитает только отправленное значение. Сборы, произошедшие во время запроса, остаются для следующего отчёта.

## Архитектура

```text
Агент → HTTP API → Storage → MemStorage
                     ↑
              чтение / HTML-список
```

| Каталог | Ответственность |
| --- | --- |
| `cmd/agent` | Сбор, отправка и жизненный цикл агента |
| `cmd/server` | Маршрутизация и жизненный цикл сервера |
| `internal/config` | CLI-конфигурация и проверка параметров |
| `internal/handler` | HTTP-обработчики, работающие через интерфейс Storage |
| `internal/repository` | Интерфейс хранилища и реализация в памяти с RWMutex |
| `internal/model` | Модель и типы метрик |

Каталоги `api`, `migrations`, `pkg`, `internal/service`, `internal/agent` и `internal/config/db` оставлены от учебного шаблона и пока не содержат реализации.

## Проверки

```sh
go build ./...
go test ./...
go vet ./...
go test -coverpkg=./... -coverprofile=coverage.out ./...
go tool cover -func=coverage.out
go test -race ./...
```

Для детектора гонок требуется поддерживаемая платформа и C-компилятор. На Windows эту проверку можно выполнить в Linux CI.

Тесты проверяют маршруты и ошибочные запросы, точность чтения gauge, накопление counter, параллельный доступ к хранилищу, проверку конфигурации, повторные отчёты агента, сохранение неотправленной дельты, таймауты и отмену запросов. Сценарий агент → обработчик → хранилище проверяется через HTTP-запросы с транспортом в памяти; запуск отдельных процессов и реальные TCP-соединения в этих тестах не проверяются.

GitHub Actions выполняет сборку, тесты, `go vet` и детектор гонок. Отдельные workflow учебных автотестов Практикума сохранены.

## Ограничения

- Данные находятся только в оперативной памяти и теряются при перезапуске сервера. Неотправленная дельта теряется при завершении агента.
- Нет истории, временных рядов, идентификаторов агентов и меток. Несколько агентов с одинаковыми именами объединяют counter и перезаписывают gauge.
- Ошибки отправки записываются в журнал; следующая попытка происходит при очередном отчёте. Протокол не обеспечивает exactly-once: если сервер применил counter, но подтверждение потерялось, повторная отправка может учесть дельту дважды.
- Нет аутентификации, ограничения количества метрик и встроенного TLS на сервере. По умолчанию сервер слушает localhost.
- Нет правил алертинга, уведомлений, постоянного хранилища и пакетного API.

Проект предназначен для изучения Go и демонстрации базового сервиса сбора метрик.
